# 쿠폰콕 AI·개인정보·데이터 준수 설계

기준일: 2026-08-20
범위: iOS 앱, Firebase, Cloud Run API/MCP/ADK, 공식 혜택 RAG

> 이 문서는 제품 설계·검토 기준이며 법률 자문이 아니다. 출시 전 개인정보처리방침, 이용약관,
> 통신사·카드사 문서 이용 조건은 법률 전문가와 제공사별로 최종 검토한다.

## 1. 적용 범위 판단

쿠폰콕은 쿠폰·통신사·카드 혜택의 후보를 제시하고 Calculator가 최종가를 산출하는 소비자 편의 서비스다.
대출 승인, 신용평가, 결제 승인, 고용·의료·공공 자격 결정처럼 이용자의 권리·의무를 직접 결정하지 않으므로,
현재 MVP는 고영향 인공지능으로 전제하지 않는다. 다만 Gemini를 사용해 OCR 초안과 추천 이유를 생성하므로
생성형 AI의 사전 고지·출력의 설명 가능성·안전 통제를 적용한다. 향후 카드 한도·신용·결제 승인 또는 자동 결제 기능을
추가하면 고영향성·전자금융·개인정보 영향평가를 별도 재검토한다.

## 2. 근거 문서와 구현 매핑

| 근거 | 쿠폰콕 적용 원칙 | 구현 또는 운영 통제 | 상태 |
|---|---|---|---|
| 인공지능기본법 제3조 및 시행령 제23조 | 생성형 AI 사용 사실과 주요 기준을 이용자가 이해할 수 있게 고지 | 첫 동의 화면에 AI 역할을 표시하고, 추천 화면에서 `AI 설명`과 `Calculator 계산 결과`를 분리 | 구현 |
| 인공지능기본법의 안전성·신뢰성 원칙 | AI가 금액·순위를 임의 변경하지 않음 | Calculator Tool이 최종가·절약액의 단일 권한이며 Gemini는 설명만 생성 | 구현 |
| 국가·공공기관 AI 보안 가이드북 | 입력 민감정보, 프롬프트 인젝션, 도구 오남용, 비인가 접근을 수명주기별로 통제 | iOS Vision OCR, 원문 이미지 기기 내 보관, PII 가드레일, strict MCP schema, 내부 토큰, 최소 권한 SA, DLP·Model Armor 단계적 적용 | 구현/배포 전 활성화 |
| 공공데이터의 인공지능 친화적 관리 가이드라인 | 출처·권리·버전·품질·계보를 함께 관리하고, stale/권리 미확인은 사용하지 않음 | `source_id`, URL, 해시, 확인일, 유효기간, 승인 상태를 문서·청크에 보관하고 candidate→approve→active만 RAG 검색 | 구현 |
| 개인정보 보호 원칙 | 최소 수집, 목적 제한, 선택 동의, 철회·삭제, 안전한 처리 | 익명/Apple 계정, 위치·개인화 선택 동의, 카드번호·CVC·거래내역·위치 이력 미수집, 앱 내 전체 삭제 | 구현 |

공공데이터 AI 관리 가이드라인은 공공기관 담당자를 주된 대상으로 하며 민간 앱에 직접 법적 의무를 부과하는 문서는 아니다.
쿠폰콕은 data.go.kr 원천의 이용 조건과 개인정보·저작권·약관 등 별도 법적 의무를 준수하면서,
해당 가이드의 출처·품질·버전 관리 원칙을 자율 통제로 채택한다.

## 3. 개인정보와 계정 처리

| 데이터 | 수집 목적 | 저장 위치·기간 | AI/외부 전송 | 사용자 통제 |
|---|---|---|---|---|
| Firebase UID | 로그인·동기화·접근 제어 | Firebase/Firestore, 계정 삭제까지 | ADK에는 HMAC 가명 참조만 전달 | Apple 로그인 연결, 계정·데이터 삭제 |
| 쿠폰 구조화 정보 | 후보 매칭·가격 계산 | Firestore 및 기기, 삭제까지 | 필요한 구조화 필드만 API 전달 | 등록 전 수정, 사용 기록 복원, 전체 삭제 |
| 쿠폰 원본 이미지 | 바코드·조건 확인 | iPhone 앱 저장소 | 전송하지 않음 | 개별 쿠폰/전체 데이터 삭제 |
| OCR 텍스트 | 쿠폰 초안 정리 | 서버 원문 저장 금지 | 바코드·연락처 등 제거 후 Gemini 정규화 요청 | 등록 전 확인·수정·취소 |
| 통신사·카드 상품·등급 | 혜택 후보 필터 | Firestore, 선택 동의 중 유지 | 최소 구조화 조건만 전달 | 선택 동의 철회·프로필 초기화 |
| 현재 위치·지오펜스 | 주변 매장 식별·진입 알림 | 기기에서 처리, 위치 이력 미보관 | 현재 좌표로 매장 조회만 수행 | 위치 동의 철회·iOS 설정 이동 |

## 4. 보안·안전 운영 기준

1. **입력 경계**: 원본 OCR·바코드·카드번호·이메일·전화번호·Firebase UID는 Agent Tool 인자로 금지한다.
2. **도구 경계**: MCP는 `search_nearby_stores`, `retrieve_carrier_benefits`, `calculate_best_discount`의 read-only Tool만 제공한다.
3. **계산 경계**: RAG 문서는 근거·조건을 제공할 뿐 할인 금액을 추정하지 않으며, 명시 규칙 없는 혜택은 `공식 확인 필요`로 처리한다.
4. **출처 경계**: 공식 URL, 확인일, 권리 상태, 해시, 유효기간이 없는 문서는 active RAG 인덱스에 승격하지 않는다.
5. **관측 경계**: 로그와 AgentOps에는 OCR 원문, 바코드, 이메일, 전화번호, 직접 UID를 남기지 않는다.
6. **실패 기본값**: RAG·ADK·공공 API가 실패하면 확인된 쿠폰 Calculator 결과만 제시하고, 근거 없는 할인·결제 가능을 단정하지 않는다.

## 5. Cloud DLP·Model Armor 전환 기준

| 단계 | DLP | Model Armor | 승격 조건 |
|---|---|---|---|
| 개발 | local redaction, `off` | `off` | 단위·Golden·가드레일 평가 통과 |
| 베타 관측 | `monitor` | `monitor` | 서비스 계정 최소 권한, 허용/차단 로그에서 원문 미기록 확인 |
| 운영 강제 | `enforce` | `enforce` | 오탐률·지연·fallback 검토, 템플릿 승인, 차단 UX 검증 |

## 6. 법령 MCP 사용 원칙

[`korean-law-mcp`](https://github.com/chrisryugj/korean-law-mcp)는 법제처 Open API 기반의 법령·판례 검색과
인용 검증 도구다. 쿠폰콕에서는 **개발·정책 검토와 문서 인용 검증에만** 사용한다.

- 사용 예: 개인정보처리방침·이용약관·데이터 보유 정책 변경 전 현행 법령 조문 및 인용 확인
- 금지: 사용자에게 개인별 법률 조언, 권리 판단, 분쟁 결론을 생성하는 추천 Agent Tool로 노출
- 운영: 별도의 법제처 Open API `LAW_OC` 키를 개발자 로컬 또는 검토 전용 Secret에 보관하며 iOS·사용자 요청·로그에 넣지 않음
- 검증: MCP 응답의 인용은 원문 링크·시행일·조회 시각을 함께 확인하고, 법률 전문가 검토가 필요한 항목은 자동 통과시키지 않음

## 7. 출시 전 외부 설정 체크

- Firebase Authentication에서 **Apple 제공업체** 활성화 및 Apple Developer의 Sign in with Apple capability 설정
- 개인정보처리방침·이용약관·고객 문의/삭제 요청 채널 공개
- Firestore Rules, App Check, 계정 삭제·동의 철회·권한 거부 복구를 실기기로 확인
- DLP Runtime SA 최소 권한, Model Armor template 및 `roles/modelarmor.user/viewer` 승인
- 통신사·카드사 문서의 수집·저장·임베딩·요약·재배포 권한을 제공사별로 검토

## 8. 핀테크 인접 서비스 경계

쿠폰콕은 카드·통신사 혜택을 비교하므로 소비자 금융 경험과 맞닿아 있지만, 현재 버전은
**결제·자금이동·정산·신용정보 전송·대출/신용 판단을 수행하지 않는 혜택 안내 서비스**로 한정한다.

| 구분 | 현재 허용 범위 | 현재 금지 범위 | 추가 전 검토 |
|---|---|---|---|
| 결제 | 사용자가 쿠폰 바코드·조건을 직접 확인하도록 안내 | 결제지시, 카드 승인, 결제대행, 환불·정산, 선불충전금 보관 | 전자금융거래법·전자지급결제대행 등록 여부, 결제사업자 계약 |
| 카드 데이터 | 카드사·상품명, 사용자가 직접 입력한 전월 실적 충족 여부·잔여 한도 | 카드번호, 유효기간, CVC, 계좌번호, 거래내역, 카드사 로그인 정보 | PCI DSS, 전자금융거래·개인정보·신용정보 규제 검토 |
| 마이데이터 | 사용자가 직접 선택한 통신사·카드 상품·등급 | Open Banking/MyData로 계좌·카드 거래·잔액·개인신용정보를 수집·통합 | 본인신용정보관리업 허가·지정기관/금융회사 계약·보안 체계 |
| 추천 | 공식 혜택 근거와 Calculator 예상 절약액 제공 | 대출·보험·투자 적합성 판단, 신용점수 산정, 결제 승인 권고 | 금융소비자보호·신용정보·광고/표시 규제 전문 검토 |

앱 추천 화면에는 “예상 결제”가 카드사·가맹점의 실제 승인 금액을 보장하지 않으며,
쿠폰콕이 결제 실행·승인을 하지 않는다는 문구를 표시한다. 이로써 사용자의 최종 선택권을 보장하고,
혜택의 중복·제외·재고·가맹점 조건은 결제 전 직접 확인하도록 한다.

### 확장 중단선

아래 기능은 제품 아이디어만으로 구현하지 않고, 법률·보안·계약 검토를 통과한 뒤 별도 프로젝트로 분리한다.

1. Open Banking·MyData API로 거래내역, 잔액, 카드 사용액을 자동 수집하는 기능
2. 결제 버튼, 결제수단 토큰 저장, 카드 승인·정산·환불·선불 포인트·현금성 리워드 기능
3. 신용점수, 소득, 소비 패턴을 이용한 금융상품·한도·대출 가능성 추천
4. 카드사·은행 로그인 정보를 취급하거나, 제공사 원문을 허가 없이 대량 복제·재배포하는 기능

이 경계는 전자금융거래법상 전자지급거래·전자지급결제대행과 자금 이동, 그리고
신용정보법상 본인신용정보관리업의 허가 영역으로 확장될 가능성을 조기에 차단하기 위한 제품 원칙이다.
